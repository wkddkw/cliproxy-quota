# OPPO / 一加负一屏卡片接入

当前状态：**未实现，缺少 OPPO 开发者账号与厂商卡片授权**。v0.1.2 的 Android AppWidget 是桌面小组件；在系统的「插件」列表出现，不代表可以添加到负一屏。用户已反馈一加 13T / ColorOS 16 的插件列表可以找到本 App，尚未确认通过 App 按钮添加成功。

## 官方接入条件

[OPPO 插件卡开发文档](https://open.oppomobile.com/documentation/page/info?id=11733)说明 CardWidget 支持在主桌面和负一屏添加卡片，并明确要求：

- 认证开发者账号，在开放平台创建普通移动应用。
- 为应用申请 Card 服务权限和授权码；授权码是正式环境必备条件，多签名须分别申请。
- 向厂商申请卡片类型 ID，提供卡片标题、分组、尺寸、包名等信息。
- 完成 SDK 接入、测试及卡片审核上线。接入资格与审批结果以厂商为准。

正式显示需要包名、签名和授权码校验。没有本应用的授权时，不能把示例项目的授权码或示例卡片 ID 当作本 App 的正式授权。开发测试环境显示也不等于普通用户的正式负一屏可用。

官方示例：[OPPO-OpenPlatform/cardwidgetsupport_android_demo](https://github.com/OPPO-OpenPlatform/cardwidgetsupport_android_demo)。示例使用 `cardwidget:1.2.3-external` 与 `smartenginehelper:1.0.23`；这些是参考版本，不能据此宣称已在 ColorOS 16 验证。

## 获得授权后的实现与验证

1. 接入厂商确认版本的 CardWidget 和 UI 引擎 SDK，实现 `AppCardWidgetProvider`、数据包与卡片布局；配置本应用的授权码、卡片 ID。
2. 复用已有供应商汇总缓存，在订阅、显示、App 刷新和清除连接时更新卡片；卡片不访问安全存储中的管理密钥。
3. 单独验证负一屏的添加、移除、刷新、点击、暗色模式、重启和系统后台限制，并核对厂商配置的展示位置。桌面小组件的测试结果不能代替负一屏验证。
4. 完成正式审核后更新兼容表和发布说明。授权和实现就绪之前，不在 App 显示可用的负一屏添加按钮。

手机上的照片、定位等运行时权限不能替代上述开发者服务授权。
